# reels-factory — 인스타그램 릴스 자동 제작 스튜디오

두 채널의 릴스를 파이썬으로 렌더한다. 새 영상은 **엔진 코드를 읽지 말고, 데이터(에피소드 파일)만 작성**한다.

| 채널 | 파이프라인 | 형식 |
|---|---|---|
| **theclasssssic (Muse)** — 고전 작품 | `vd_engine.py` + `episodes/<slug>.py` | 내레이션 없음, 동화처럼 풀어가는 스토리 텍스트 릴스(자막 3~5초), 45~60초, 브리프 `docs/theclasssssic_brief.md` |
| 줌테일 | `run_zoomtale_auto.py --topic "..."` | Claude 대본 → Wikimedia/Flux 이미지 → ElevenLabs/`say` 음성 → Ken Burns, 30초 내외, 브리프 `docs/zoomtale_brief.md` |

## 환경
- 최초 1회 `./setup.sh` (python3.12 venv, ffmpeg는 imageio-ffmpeg 번들). 실행은 항상 `.venv/bin/python`.
- `.env`에 `ANTHROPIC_API_KEY` / `ELEVENLABS_API_KEY` / `FAL_KEY`. 없으면 자동 폴백(내장 대본 / macOS `say` / Commons-only) — 폴백은 `output/<ep>/build_report.json`·로그에 기록되므로 결과 보고 시 반드시 명시.
- 산출물: `output/<slug>/` (`*_sfx_only.mp4` = 마스터, `*_upload.mp4` = 인스타 업로드본(Drive에 올라감), `*_preview_bgm.mp4` = 미리보기용, `credits.json` = 출처).

## theclasssssic 에피소드 워크플로우
**제작 스킬: `/classic-reel [작품]`** (어느 세션에서든, 절차는 `.claude/skills/classic-reel/SKILL.md`). 아래는 그 세부.
1. 주제 접수 → 1차 출처로 사실 확인 → `docs/theclasssssic_brief.md` 양식으로 대본(주제문·교훈·세 문장 요약·비트표) 작성 → **연결 점검**(아래 제작 원칙 1) → 사용자 확인 후 진행.
2. `episodes/arnolfini_mirror.py`를 참고해 `episodes/<slug>.py` 작성: `TOTAL, BRAND, CAPTION_STYLE, BGM_STYLE, XFADE, MOTION_BUDGET, QUERIES, P(좌표), build_sources(ctx), SHOTS, CAPTIONS, SFX`. 좌표는 원본에 격자를 그려 확정하고, 렌더 전 **스토리보드 1장**(각 컷 첫 프레임)으로 크롭 확인.
   - `build_sources(ctx)`는 `SHOTS`의 `src` 키 → PIL RGB 플레이트(9:16 기준 최소 2160x3840, 초밀착 크롭용은 3240x5760). `ctx.fetch(key)`(Commons, QUERIES 순서대로) / `ctx.cover(img,w,h)` / `ctx.fiber(img,rng)` / `ctx.load_font(size)` / `ctx.GOLD` 제공. 실사가 없으면 절차 생성(Pillow)으로 폴백해 항상 렌더 가능하게.
3. 스모크 테스트 `--seconds 6` → 전체 렌더 `--no-bgm` (업로드본) → 필요 시 미리보기본.
4. **검수(필수)**: `.venv/bin/python review.py --episode <slug>` → FAIL 0이어야 통과. 이어서 **자막-화면 정렬 그리드**: 자막마다 그 시점 프레임을 뽑아 4장 이내 배치(한 장에 4프레임, 폭 340px 이상 — 작은 썸네일은 오판한다)로 확인. 자막이 가리키는 대상이 보이는지, 엔딩이 앞 자막에서 이어지는지 본다.
5. **배포**: `.venv/bin/python publish.py --episode <slug>` → 업로드본(`<slug>_upload.mp4`, 6Mbps·48kHz) 생성 후 Google Drive `내 드라이브/reels-factory/<slug>/`에 업로드. `caption.md`가 있으면 복붙용 `<slug>_caption.txt`(제목·게시 전 확인 메모 제외)도 같은 폴더에 함께 업로드(rclone, 최초 1회 `rclone config create gdrive drive scope=drive.file` 브라우저 승인 필요). 줌테일은 `publish.py --path output/zoomtale/final_zoomtale_reel.mp4 --name <slug>`.
   - 업로드가 실패하거나 멈추면 `publish.py`를 그대로 다시 실행(같은 파일은 건너뜀, 60초 네트워크 타임아웃·재시도 내장). 같은 이름 파일이 Drive에 둘 생기면 `rclone dedupe --dedupe-mode newest gdrive:reels-factory/<slug>`(중복본은 Drive 휴지통으로).
   - 알려진 유지보수: rclone 공용 client_id가 2026년 중 폐기 예고. 업로드가 401/403으로 실패하면 사용자에게 https://rclone.org/drive/#making-your-own-client-id 로 개인 client_id 생성 후 `rclone config update gdrive client_id=... client_secret=...` 안내(사용자 계정 작업이므로 대신 하지 말 것).
6. 보고: 파일 경로, Drive 경로, 길이, 검수 결과(이동 횟수/예산, 이음새, FAIL/WARN), 어떤 소스가 폴백됐는지, `credits.json`의 CC BY-SA 출처 표기 필요 여부. 리듬의 최종 판정은 사용자의 휴대폰 10초 시청 — 요청할 것.

### SHOT 스펙 (`S(start, src, dur=1.5, **kw)`)
| 키 | 의미 |
|---|---|
| `z=(z0,z1)` | 줌 배율 시작→끝 (1.0 = 플레이트 폭 전체). 회전 컷은 z≥2.2 |
| `f=((x0,y0),(x1,y1))` | 포커스(플레이트 정규좌표) 시작→끝 = 팬 |
| `ease` | `linear`/`in`/`out`/`inout` |
| `rot=90, rot_anim=0.35` | 회전 각도, 애니메이션 시간(0이면 즉시) |
| `bw=0.3` | 흑백 전환 시간(0 = 처음부터 흑백) |
| `invert=True` | 네거티브 반전 |
| `sat=(1.0,1.7)` / `blur=(0,16)` | 채도·블러 시작→끝 |
| `shake=14` | 카메라 흔들림(px) |
| `subcuts=[(포커스 or MARKS키, z), ...]` | 컷 안에서 균등 분할 하드컷 |
| `split=("lr"\|"tb", src2), z2=(a,b)` | 화면 분할, 두 번째 소스 줌 |
| `overlay={"type":"circle","at":(x,y)}` / `{"type":"arrows","points":{name:(x,y)}}` / `{"type":"polyline","points":[(sx,sy)...],"dashed","dots","arrowhead","ring_start"}` | 오버레이(circle/arrows는 플레이트 좌표, polyline은 화면 좌표) |

| `drift=(dx,dy)` | 인지 안 되는 미세 팬(≤0.5%) — 정지 컷에 생기 부여 |
| `XFADE=0.25` (에피소드 상수) / `xfade=0.6` (컷별) | 컷 사이 디졸브, 컷별로 덮어쓰기(막 전환). `CAPTION_STYLE="clean"` = 박스 없는 자막(기본) |
| `QUERIES[key] = "File:..."` | Commons 파일 제목 지정 → 원본 해상도 다운로드(명화 디테일용) |
| `flash=True` | 컷 시작 0.1초 화이트 플래시(반전 지점 전용) |
| `wipe={"src2","z2","from":1.0,"to":0.5,"time":0.6}` | 한 화면에서 경계가 이동하는 좌→우 와이프(두 소스 비교) |
| `mask_reveal={"src","z","f","to":(x,y,w,h),"time":1.4}` | 앞 컷의 화면이 인셋으로 줄어들며 배경(`src`)을 드러냄 — 초밀착→전경 전환용 |
| `tiles={"grid":(3,5),"mode":"reveal"\|"spotlight","seed","index":[...],"dim":0.12}` | 조각내기: 비트마다 조각 채움 / 일부 조각만 밝게 |
| `move=True` | 검수용 표식: 의도된 카메라 이동 컷 |
| `path=[(fx,fy,z), (fx,fy,z), ...], path_times=[0,0.3,0.6,1.0]` | **한 컷 안에서 여러 지점을 도는 느린 이동.** 두 대상을 한 문장으로 잇는데 둘 다 같은 그림 안에 있을 때, 컷을 나누는 대신 카메라가 지점 사이를 이동(구간마다 inout 이징이라 지점 근처에서 자연히 느려짐 = 멈춘 듯한 느낌). `path_times` 생략 시 균등 분할 |
| `render=fn(src, p, local)` | 에피소드가 직접 그리는 화면(1080x1920 RGB 반환). 엔진 기능으로 안 되는 연출용 — 예: 〈대사들〉 왜상 해골을 펴는 애니메이션(`episodes/ambassadors_skull.py`의 `anamorph`) |
| `cite="Friedman, 2000"` | 인용 슬롯(자막 띠 하단 작은 글자). 주장·근거·반례·한계 컷에 붙인다 |
| `overlay={"type":"callout","at":(px,py),"text","side":"left"\|"right","dy"}` | 관찰 지점 → 지시선 → 라벨(분석 흔적). 컷당 하나 |
| `overlay={"type":"tags","items":[(sx,sy,"로비"),...]}` | 비교 대상 이름표(화면 좌표) |
| `overlay={"type":"measure","a":(sx,sy),"b":(sx,sy),"text"}` | 치수선 + 라벨 |
| `overlay={"type":"box","rect":(x,y,w,h),"text"}` | 영역 강조 + 이름표 |

`CAPTIONS = [(start, end, text, 섹션라벨)]` (라벨: "관찰 01 · 바닥재" / "근거" / "반례" / "결론", 훅·엔딩은 ""), `SFX = [(time, "swoosh"|"ting"|"tick"|"low")]` (tick = 주석 클릭, low = 반전의 낮은 울림), `GOLD_CAPTIONS=(a,b)` 구간 자막은 골드.
에피소드 상수(현행 기본값, 에피소드에 명시): `CAPTION_STYLE="clean"`, `BGM_STYLE="calm"`, `BRAND=("","","")`, `XFADE=0.25`, `MOTION_BUDGET=4`. (`editorial`/`pulse`/섹션 라벨은 옵션 도구)
`ctx.text_card(lines, title)` → 출처/근거 텍스트 카드 플레이트. 도식(평면도 등)은 에피소드에서 Pillow로 절차 생성(`gen_maze` 참고).
마지막 컷은 0초 프레임과 같은 소스·줌·포커스로 끝내 무한 루프.

제작 규칙은 사용자 피드백으로 확정됨(2026-09-13~24). 이전 방식(1.5초 템포, 편집자 자막·섹션 라벨, 매 컷 줌, 컷마다 다른 피사체 강제)은 전부 폐기.

### 1. 이야기 — 가장 중요
- **목표는 "엥?"이 아니라 "오호라".** 한 번 본 사람의 70% 이상이 무슨 이야기였는지 세 문장으로 다시 말할 수 있어야 한다.
- **동화 읽어주듯.** 정보를 나열하지 않고 이야기로 끌고 가되, 끝에 이야기가 하려는 말(교훈) 하나가 또렷이 남게 한다. 억지 드라마는 금지 — 그 대상을 둘러싼 실제 사실이 가진 이야기의 모양을 찾는다.
- **뼈대 (이 순서):**
  1. 주제문(첫 자막): 영상 전체가 무슨 이야기인지 예고하는 한 문장. 보통 "모두가 믿어온 것". 예) "이 그림은 오랫동안 '결혼식 그림'으로 읽혔다."
  2. 뒷받침: 주제문을 믿게 만든 증거 2~3개를 하나씩 → 중간 요약 한 줄. 예) "모든 게 결혼식처럼 보였다."
  3. 반전: "그런데" + 반드시 이유/출처 + 새 사실. 예) "그런데 학자들이 이 남자를 추적하다가, / 그의 첫 아내가 이미 세상을 떠났다는 걸 알아냈다."
  4. 질문: 반전이 만든 질문 하나. 답이 없으면 없다는 걸 분명히 하고 단서로 넘긴다. 예) "화가는 답 대신 단서 하나를 남겼다."
  5. 단서: 화면에서 직접 보이는 것 하나(두 대상 비교면 한 컷 안에서 카메라로 잇기).
  6. 결론: 평서문으로 한 번 명시. 시적인 문장으로 결론을 대신하지 않는다. 예) "결혼식이 아니라, 떠난 아내를 기억하는 그림이라고."
  7. 여운: 결론 다음에 감정/질문 한 줄.
  8. 정적 → 루프: 자막 없이 2~3초, 첫 장면과 같은 화면. **루프는 문장이 아니라 첫 장면이 만든다** — 결말을 알고 다시 보는 주제문이 다르게 읽힌다.
- **연결 점검 (대본 단계, 렌더 전 필수):**
  - 인접한 두 자막마다 "앞 문장 없이 뒷 문장이 왜 나오는지 설명되는가?" "그래서/그런데/그럼"으로 시작하면 앞 문장과 실제 인과·대조 관계가 있어야 한다.
  - **마지막 자막은 바로 앞 자막에서 자연스럽게 이어져야 한다. 루프를 위해 첫 문장과 억지로 잇는 연결 문장을 만들지 않는다** (실패 예: 여운 문장 뒤 "그래서였을까, 결혼식 그림으로만 남았다." → "급하게 마무리하는 느낌").
  - 정보를 줄일 땐 이야기의 관절(반전의 이유, 질문의 처리, 결론)은 남긴다. 줄였더니 이해가 안 된 사고가 있었다(v6). 날짜·인명 비교처럼 화면에 대응 이미지가 없는 세부는 캡션으로 보낸다.
  - 자막만 이어 읽고 세 문장 요약이 나오는지 확인한다.
- **사실:** 스토리가 기대는 사실은 렌더 전에 1차 출처(박물관 공식 설명 등)로 확인하고, 위키백과 등과 다르면 1차를 따른다. 소수설은 영상에선 "어떤 학자들은", 캡션에선 "정설은 아니다"로 한정. 역사적 사실만, 실존 인물 비방 금지.

### 2. 문장
- 사람이 쓴 말투, 소설 내레이션처럼: 보이는 건 현재형("~있다"), 역사는 과거형("~했다"). 상징은 하나씩 풀이하지 말고 문장에 녹인다.
- 금지: 느낌표, "놀랍게도", "숨겨진 진실", "~의 진실" 남발, "단서 1.", "A = B" 같은 정형구, 팔로우 유도("알고 계셨나요? 팔로우").
- 한 줄 ≤ 15자, 2줄까지, 줄바꿈은 `\n`으로 직접.

### 3. 편집
- **컷은 "보여줄 대상"이 바뀔 때만.** 자막이 말하는 대상이 화면에 보여야 하고, 대상이 그대로면 자막이 바뀌어도 컷하지 않는다(한 컷에 자막 2개 OK — 그만큼 컷을 길게).
- 같은 그림 안의 두 대상을 잇는 문장은 컷 대신 `path`로 카메라가 이동한다. 카메라 이동은 이야기상 의미 있을 때만, 느리게, 4회 이내. 줌인·줌아웃 반복 금지.
- 같은 구도 반복 금지. 단 의도적 콜백 1회는 권장(같은 투샷에 앞에선 "결혼식처럼 보였다", 뒤에선 "다르게 읽는다").
- 디졸브 `XFADE=0.25`, 막 전환 `xfade=0.6`. 플래시·자막 페이드·깜빡이는 요소 금지. 비네트 금지(필름 그레인만).
- 자막 `CAPTION_STYLE="clean"`(박스 없음), 화면에 브랜드 텍스트 없음(`BRAND=("","","")`). 오버레이는 기본 없음, 필요하면 컷당 하나(얇은 원/지시선).
- **자막 리듬:** 하나당 3~5초(최소 2.8초), 직전보다 30% 넘게 짧아지지 않게, 읽기 속도 ≤ 6자/초. 갑자기 빨라지는 구간이 있으면 내용을 놓친다.
- 길이: 이해가 우선, 보통 45~60초, 최대 60초. 내레이션 없음(트렌딩 BGM 전제), SFX는 반전 한 번(`low`).
- **완성 에피소드(기법 참고용):** `arnolfini_mirror`(기록의 반전, 콜백 투샷) · `ambassadors_skull`(여백 판 `pad` + `render`로 왜상 해골을 화면에서 펴기) · `arcimboldo_gardener`(`render`로 그림 뒤집기, `sat`으로 색이 빠졌다 돌아오는 '잊힘→재발견') · `icarus_fall`(`path`로 풍경을 훑다 작은 주인공에게 다가가기, 16배 초근접).
- **기준작: `episodes/arnolfini_mirror.py`.** `episodes/casino_carpet.py`는 폐기된 v3 실험작이자 채널 컨셉 밖(현대 소재) — 참고하지 않는다.

### 옵션 도구 (기본 사용 안 함, 사용자가 요청할 때만)
섹션 라벨·인용 슬롯(`cite`)·콜아웃·치수선·출처 카드·도식, `flash`, `tiles`, `wipe`, `mask_reveal`, `shake`, `CAPTION_STYLE="editorial"`, `BGM_STYLE="pulse"` — 영상을 빽빽하게 만들어 이탈을 부른 전례가 있다.

## 기타 규칙
- 줌테일: 훅은 이미지 특정 부위 타격 질문, 자막 3~4단어, 결론은 마지막 5초 전까지 유보, 마지막 문장이 훅으로 이어지는 루프 + 저장 CTA.
- Commons 이미지는 **퍼블릭 도메인/CC0/CC BY 우선**(BY-SA는 영상 전체에 동일 라이선스 표기가 원칙이라 가급적 피함). `credits.json` 기준으로 `output/<slug>/caption.md`에 캡션을 함께 만든다.
- **캡션 = 영상은 이야기, 캡션은 근거.** 문어체 '~다'. 첫 줄은 영상의 주제문과 같은 문장(40자 이내). 확인 가능한 고유명사(인명·연도·출처), 영상에서 단순화한 부분의 정정, 소수설 한정("정설은 아니다"). 대칭 나열·이모지·느낌표·'핵심은 다음과 같습니다' 금지, 문장 길이 섞기. 600~900자. 끝에 해시태그 10개 내외 + 사진 출처. 사실 확인이 필요한 항목은 캡션 끝 괄호로 표시해 사용자에게 검증 요청(`publish.py`가 복붙본에서 자동 제외). 프로필 문안은 `docs/instagram_profile.md`.

## 검수 기준 (`review.py`가 자동 검사)
1. 카메라 이동 횟수 ≤ `MOTION_BUDGET`(기본 5).  2. 이동 중 컷 금지.  3. 자막 읽기 속도 >7자/s FAIL, >6 WARN.  4. **자막 길이 <2.8초 FAIL**(너무 빨리 지나감).  5. **직전 자막보다 30% 넘게 짧아지면 WARN**(자막 전환 급가속 — 내용을 놓치게 됨).  6. 컷별 첫|끝 프레임 모션 점수: 지정(`move`/효과) 안 된 컷에서 움직임이 감지되면 FAIL.  7. 루프 이음새(첫 0.27s vs 끝 −0.31s, 자막 띠 제외) diff ≤ 0.08.  8. 모션 시트 육안: 자막 안전 영역, 오버레이 명중, 효과(반전/회전/분할/타일) 실제 적용, 이스터에그 존재.
검수는 정지 프레임+데이터 대리검사다. **자막-화면 정렬(자막이 가리키는 대상이 실제로 보이는지)과 스토리 논리는 자동 검사 대상이 아니다 — 타임코드 그리드로 직접 확인한다.** 실제 리듬·어색함은 사용자 시청이 최종 게이트.

## 엔진을 고칠 때 (다른 포맷 실험 포함)
- `vd_engine.py`·`review.py`·`publish.py`는 완성된 4편이 쓰고 있다. 새 포맷을 위해 고치면 기존 동작을 바꾸지 말고 **새 키·새 옵션을 추가**하는 방식으로만 고친다.
- 고친 뒤엔 기존 에피소드 4편(`arnolfini_mirror`, `ambassadors_skull`, `arcimboldo_gardener`, `icarus_fall`)을 `--seconds 3`으로 스모크 테스트한다.
- 다른 채널·포맷의 규칙은 이 문서의 theclasssssic 섹션에 섞지 말고 별도 섹션(또는 별도 폴더)으로 둔다.

## 토큰 규칙
- 엔진(`vd_engine.py`, `run_zoomtale_auto.py`)은 읽지 않는다 — 스펙은 이 문서에 있다. 수정이 필요할 때만 해당 함수 범위만 읽는다.
- 에피소드 파일은 `episodes/arnolfini_mirror.py`를 한 번만 참고하고, 이후 에피소드는 데이터 블록만 작성/패치.
- 렌더 출력은 `| tail -1`, 검증은 스토리보드 1장 + 자막-화면 정렬 그리드(4장 이내), 응답은 결과·폴백·다음 행동만 짧게. 영상 1편 목표: 20~30K 토큰.
